# Memory Policy

## Purpose

Keep durable memory small, useful, and safe. Markdown is the canonical source; search indexes and generated reports are disposable views.

## Write Rules

- Never store passwords, tokens, recovery codes, browser cookies, or private keys.
- Record only reusable preferences, corrections, validated workarounds, recurring failures, and stable project decisions.
- Put short chronological notes in `SESSION_LOG.md`; promote durable items into `PROFILE.md`, `ACTIVE.md`, `LEARNINGS.md`, `ERRORS.md`, or `FEATURE_REQUESTS.md`.
- Keep `ACTIVE.md` concise. Remove or supersede stale rules instead of letting startup context grow without bound.
- Use UTF-8 and preserve the user's original wording when uncertainty matters.

## Review

Periodically compact old session notes, deduplicate repeated guidance, and verify that promoted rules are still current.
