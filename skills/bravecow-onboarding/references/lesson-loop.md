# 单课互动与恢复

## 正常回合

按固定顺序组织，但不显示小标题：

1. `第 n/m 课 · 当前主题`
2. 一句“为什么这一步有用”。
3. 一个当前项目或中性例子。
4. 一个可在本轮完成的小动作。
5. 一个短问题，确认用户看到了什么。

一轮只要求一个动作。需要多次点击时，先完成当前点击并等待结果，再给下一张图。

## 回应学习结果

- **完成**：只指出一个具体做对的地方，然后进入下一检查点。
- **部分完成**：保留已完成部分，只纠正一个会影响结果的问题。
- **卡住**：判断是界面变化、权限、前置概念还是动作过大；只处理最可能的一项。
- **回答超出课程**：先直接回答，再判断是否需要重排路线；不要用课程结构挡住问题。
- **用户说“不知道”**：给两个具体选项或一个最小示范，不要求长篇自述。

## 失败恢复

同一动作第一次失败：重新读取可见结果，给一个更小的安全重试。

同一动作第二次失败：停止重复操作，说明原因属于哪一类，并改用替代路径或前置微课。

界面证据不足：直接说“你这里的界面和课程图不一样，我重新看一下实际按钮”；现场核验后再教，不让用户盲找。

权限或对外动作受阻：保留草稿/预览，把确认点交还用户；不要把降低安全边界当作教学捷径。

## 暂停与恢复

暂停时只保存三项课程状态：

- `目标/路线`：真实项目或软件与原理。
- `已完成`：最后一个通过检查的能力。
- `下一步`：一个具体动作。

恢复时用一行重述这三项，不回放整段课程，也不重新收集个人信息。

## 目录与跳课

用户说“目录”时，只列：已完成、当前、接下来最多 3 个候选模块。用户说“跳过”时，记录为跳过而非掌握；若它后来成为必要前置，再用一句话说明原因并征求是否补上。
