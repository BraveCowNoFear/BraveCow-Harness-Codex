# 自适应课程目标池

这不是固定课表。根据用户的专业或职业、技术基础、真实目标、运行时、当前界面和回答，选择、排序、合并或跳过模块。优先形成早期真实成果，再补支撑它的机制。

## 路由原则

1. 必选起点：先让用户选择“真实项目路线”或“只熟悉软件与原理路线”。
2. 按需核心：上下文、需求表达、计划、权限、工具、模型、验证。
3. 专项分支：Git/GitHub、Automation、Computer Use、Skills、插件、Harness、人物方法镜头。
4. 项目路线终点：个人项目的小交付、真实成品检查、个人速查表。
5. 原理路线终点：一组中性微练习、真实结果检查、软件与原理速查表，不虚构毕业项目。
6. 已掌握的内容用一个动作验证后跳过；不要为了凑课数保留。

## 模块池

### A. 新任务与上下文

理解任务是一段独立对话上下文；能判断继续当前任务还是另开任务，并在任务列表中安全切换。

### B. 项目与工作区

区分任务、项目/工作区和长期目标；新建或打开真实项目文件夹，并辨认当前的本地、云端、Worktree 或远程环境。

### C. 需求四件套

把真实需求表达成目标、材料、限制和完成标准；只追问会改变方案的缺口。

### D. 计划与检查点

方向不明、选择会改变结果或风险较高时先计划；简单明确的工作直接执行。计划包含里程碑、风险、确认点和验收标准。

### E. 版本、Git 与 GitHub

普通文档使用副本/历史版本；本地仓库学习 `git status`、`diff`、`commit` 和回退；只有需要远程协作或发布时才进入 `remote`、`push` 和 PR。

### F. 长期目标

跨阶段、需要持续追踪的结果才使用 Goal。把目标拆成 3-5 个可验证里程碑、停止条件和复盘点。

### G. 模型与思考策略

只教当前界面真实可选项。根据任务难度、速度、可靠性、成本和审查需要选择模型与思考策略；没有独立思考等级控件时不得伪造。

### H. 材料、网页与工具

区分附件、联网检索、浏览器、Computer Use、Automation 与普通文件操作。按信息来源、权限、可逆性和是否对外选择工具。

### I. Skills、插件与 Harness

理解 Skill 是可复用工作方法，插件增加外部能力，Harness 组合 Skills、插件、规则、记忆和检查机制。人物方法镜头提供流程和边界，不冒充本人或伪造原话。

### J. 个性化毕业项目

从第一课的真实目标中选择一个 20-40 分钟可闭环的小交付。先澄清，再计划或执行，生成真实文件，打开成品，对照标准修复，最后由用户决定是否对外动作。

### K. 无项目原理路线

不要求用户填写目标、材料、限制或完成标准。围绕当前软件依次用极小中性动作讲清任务/上下文、工作区、计划与执行、权限、模型与工具、Skills/Harness、真实验收；每个动作随做随解释因果，不构造贯穿项目。

## 深度适配

- 技术/科学：讲上下文注入、文件系统、沙箱、权限、状态、版本、数据流、失败模式和验证；练习可使用代码、数据、实验、CAD 或工程项目。
- 非技术：保留正式术语与真实因果链，先给白话定义；练习来自业务、学习、创作或生活项目。
- 无法判断：采用“准确术语 + 一句定义 + 一个真实动作”，根据回答加深或简化。

## 动态调整信号

- 连续两次独立完成：提高开放度或验证要求。
- 同一步两次失败：缩小动作、重新检查 UI 或补一个前置概念。
- 目标变化：立即重排后续路线，不维护形式上的固定课数。
- 用户说“只想做出来”：先完成最小闭环，再用结果解释机制。
- 用户说“想学底层”：增加边界、数据流、失败模式与反例。

## 完成判定

项目路线完成时，用户应能独立完成与自己目标有关的小项目。原理路线完成时，用户应能独立操作当前软件并说明：助手看到了什么、做了什么、哪里需要确认、如何回退、怎样检查真实结果。
