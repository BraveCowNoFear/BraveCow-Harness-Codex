# 执行、版本与外部动作分支

只在用户的真实任务需要时进入对应分支。无项目原理路线可以解释差异，但不要求配置 Git 或 GitHub。

## 先按交付物分支

### 普通文档或素材

使用副本、文件历史、版本号或可恢复保存。练习目标是“知道改了什么、能比较、能恢复”，不引入 Git 术语负担。

### 本地工程或仓库

先只读检查 `git status` 和 `git diff`，再解释 `commit = 本地可命名版本点`。只提交本轮相关文件，不覆盖用户既有改动；回退前先确认目标和影响范围。

### 需要远程协作或发布

在本地版本点之后再解释：`remote = 远程仓库地址`、`push = 把本地提交上传`、`PR = 请求合并和审查`。执行 push、开 PR、合并或发布前复核仓库、分支、提交范围和可见性。

## 动作风险梯度

| 动作 | 默认处理 | 教学重点 |
|---|---|---|
| 读取本地材料 | 可直接进行 | 说明可见范围与隐私 |
| 创建本地草稿 | 可直接进行 | 指出保存位置与回退方式 |
| 修改已有文件 | 先确认范围 | 保护未授权和既有改动 |
| 联网查询 | 说明会联网 | 区分外部事实与本地材料 |
| push / 发消息 / 发布 | 执行前确认 | 目标、内容、受众、可见性 |
| 删除 / 覆盖 / 付款等高影响动作 | 精确复核并保留恢复路径 | 不把完全访问当作默认捷径 |

## 教学动作

1. 先让用户判断当前任务属于哪条版本分支。
2. 显示 `assets/ui/shared/06-version-flow.png`，只解释选中的一行。
3. 创建一个真实且可恢复的版本点。
4. 让用户说明下一步是否会越过本地边界。
5. 只有答案为“需要”时才展开 GitHub 或其他外部动作。

## 常见纠正

- `commit` 不等于已经上传 GitHub。
- 保存文件不等于建立了可比较的版本历史。
- `完全访问` 不代表每个外部动作都无需确认。
- 构建、预览或测试通过不等于已经发布。
- 非技术用户不需要为了“正规”而被迫学习命令行。
